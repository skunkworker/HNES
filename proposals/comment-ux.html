The baseline

Today a comment is a card. The vote column and the collapse button sit in a fixed gutter, the body indents 54 px to clear both, and nesting is carried by a 2 px spine. It is correct and it measures clean — but the collapse control is still a 26 px square, and the header carries five separate elements before the first word of the comment.

Direction one

Rail

Medium · structural

Collapse the gutter into a single control surface. The vote arrows, the collapse action and the thread spine become one continuous rail running the full height of the comment — so the collapse target grows from 676 px² to the whole left edge, and the header loses two elements.

What changes

  • .hnes-comment becomes a two-column grid: rail, then pane.
  • The .collapser element goes away entirely — the rail owns the click.
  • The spine moves off .replies and onto the rail, so hovering a subthread lights the comment it belongs to rather than a line beside it.
  • Body indent drops 54 px → 30 px, which buys back real width at depth.
  • [+]/[–] is replaced by rail state; the reply count pill carries the collapsed signal.

Cost

Template change in renderComment plus a rewrite of the comment block in the stylesheet. The rail must be a real <button> for keyboard reach — currently the collapser is an <a> with no href, which is not focusable.

Direction two

Density

Low · tokens only

One control, three settings, no new layout. Comfortable is today's card. Compact tightens the gaps. Dense drops the card entirely and falls back to hairline-separated rows — closer to what HN veterans actually want on a 400-comment thread.

What changes

  • A data-hnes-density attribute on <html>, set by boot.js before first paint exactly like the theme already is.
  • Three token blocks overriding --hnes-gap-*, --hnes-size-comment and --hnes-leading. Nothing else.
  • A second nav control beside theme: auto, reusing the same cycle-and-persist code path.

Cost

The cheapest of the three by a wide margin, and the token audit already proves the groundwork is there — 62 tokens, none unused, no hardcoded literals left in the comment block. This is close to configuration rather than design work.

Direction three

Focus

High · behavioural

The extension already knows which comments you have seen — it stores a per-thread read position and ships .hnes-new markers nobody really looks at. This direction promotes that data from a border colour to the organising principle of the page.

What changes

  • Comments read on a previous visit dim; new ones keep full contrast and take an accent edge.
  • A thread minimap down the side — one tick per top-level comment, new ones lit, current position marked. Click to jump.
  • n / p to move between unread comments, building on the keyboard work already queued for the e.keyCode migration.
  • The dimming is a toggle, not a mode — one control returns everything to full contrast.

Cost

The largest, and the only one that changes behaviour rather than presentation. It also leans on the read-state store, which currently has no expiry sweep — that gap should be closed first or the store grows without bound.

Side by side

DirectionEffortTouchesPayoffMain risk
Rail Medium Template + comment CSS Much larger collapse target; 24 px width back at every level Touches the markup every other rule depends on
Density Low Tokens + one nav control Serves scanning and reading without picking one Dense mode needs its own contrast pass
Focus High Read-state JS, keyboard, minimap Makes revisiting a live thread genuinely fast Behaviour change; depends on an unbounded store

Recommendation: Density first, then Rail. Density is nearly free — the token layer is already complete and audited, so it is a config change wearing a design proposal's clothes, and it settles the scanning-versus-reading argument without committing the layout to either.

Rail is the one with the real design payoff, but it rewrites the markup that the entire comment stylesheet hangs off. Worth doing on its own, with the geometry checks from this session re-run against it. Focus is genuinely valuable and genuinely the largest — and it should wait until the collapse-state store has an expiry, since it would lean harder on exactly the data that currently grows forever.
